## 两项 V1.0 修复（用户「两个都做」授权，已交付，未提交）

### ⑴ 已完成分组展开时重复渲染
根因：`visibleGroups` 只在折叠时排除 `.done`，展开后 `TodoListView:68` 与 `:299` 折叠头
各画一遍。修法：`visibleGroups` 一律 `filter { $0.kind != .done }`，「已完成」由
`completedToggleBlock` 独占渲染。
- 测试：`TodoListViewModelTests:110-121` 原断言「展开后含 `.done`」正是在钉这个 bug，
  改写为「展开也不含」+ 合并两处渲染源后无重复 id + `groups.count == visibleGroups.count + 1`。
- 验收凭据：UI 套件 DUP 探针 `COUNT[list-root] "todo.row.menu.续费会员.done"` 从 2 → 1。

### ⑵ 30ms 墙钟用例 —— 热缓存这条路是死的
实测：同一 context 连跑，warm 从不低于 38.5ms，有两次比 cold 还慢
（cold/warm：40.9/43.8、43.7/45.6、39.5/38.5、44.9/51.6、40.7/40.8）。

**真正的结论（以后直接引用，别再量一遍）：SwiftData 逐行 materialize ≈17µs/行。**
分段探针（同一 context 三轮一致）：空谓词 fetch 0.3ms / 排序 fetch 30-35ms /
不排序 fetch 28-33ms / 标量循环 1.5ms / 关系循环 3.9ms。
`detect` 实测 40.8ms ≈ 35 + 1.7 + 3.9，等式严密对上。
→ **全表扫的时间基本全是 SwiftData 的，不是我们的算法**；1 万行 ≈200ms（实测 201.0/204.2）。

修法（改了生产代码）：`Diagnostics` 加值类型投影 `EntrySnapshot` + 纯函数 `scan(_:today:)`，
`detect` 瘦身成 fetch → 投影 → scan → 订阅 ⑤。语义逐字保持（①①b②③④ 全部搬进 `scan`）。
测试拆两条各守一层：
- `testScanTwoThousandEntriesUnder30Milliseconds`：喂 2000 个值类型，实测 0.5-0.6ms，
  预算 30ms（50 倍余量），同时断言四项计数 —— 真守门员。
- `testDetectTwoThousandEntriesUnderCoarseBudget`：全路径，预算 300ms，只防
  「每条加一次 fetch」和「改成 O(n²)」两类事故，不承担回归灵敏度。

### 顺手更正的两个假数字（都是同一个错）
- `Diagnostics.swift:31` 文件头原写「全表扫（≤1 万行）< 30ms」—— 假，错约 6 倍。已换成实测口径。
- `ScenePhaseCoordinator.swift:155` 原写「1 万行 ~5ms」—— 假，差约 40 倍。已换成 ≈200ms。
  只动注释，逻辑没碰；这个数字反而更支持「启动自检只跑一次」的决定。
